# v0.0.4 — NFP / IFP, BLF and Guided Local Search

## Implemented

- The production Worker now calls `runGlsNesting`. The previous engines remain available for regression tests and comparison.
- Adaptive DXF polygonization uses millimetres after the existing unit normalization. Arc/ellipse subdivision uses chord error; rational spline evaluation subdivides knot spans and tests quarter/midpoints recursively. Half the tolerance budget is reserved for removing redundant samples. The default is 0.1 mm, adjustable from 0.001 to 5 mm. Native DXF primitives and spline control data are retained for export.
- Open curves are reported and excluded from the part catalogue. Invalid closed contours, self-intersections, degenerate edges, malformed spline data and holes crossing an outer boundary produce errors. Small open endpoint gaps are not silently closed. Explicitly closed polylines keep their DXF closing edge.
- The forbidden translation region is the union of convex-cell Minkowski sums `A_i + (-B_j)`, with a single offset for the edge-to-edge gap. Earcut decomposes the complete solid including holes; neighbouring triangles merge only if their union is convex and area preserving. Taking the hull of sums of vertices of two convex cells is exact for those cells; the original concave part is never replaced by its convex hull.
- The IFP is calculated from the extrema of the actual rotated contour inside the rectangular material. Clipper subtraction exposes feasible contact boundaries and cavities. Degenerate IFPs, where a shape fits exactly in one dimension, also generate line/point contacts.
- NFP caching uses the entire quantized geometry, including rotated coordinates and holes, plus gap and integer scale. Identical copies share cached geometry. Caches are bounded (256 NFP entries and 128 decompositions) and persist across Worker jobs.
- First a fast, contour-checked contact layout is saved as a safe incumbent. Area, height and width orders provide multiple starts. Time-limited NFP/BLF starts search feasible contact regions and smaller pieces in existing gaps before extending rows or opening another sheet. Short deadlines may prevent an NFP start from finishing; the validated contact incumbent is retained.
- GLS has persistent feature penalties, not random restarts. Features describe an instance's sheet, rotation and 20 mm spatial bin. At a local minimum of the sampled neighbourhood, maximum-utility features `cost / (1 + penalty)` are penalized. Acceptance uses the physical objective plus `0.15 / instanceCount * sum(active penalties)`.
- Neighbourhoods include translation, permitted rotations, order swaps, remove/reinsert and controlled reconstruction of penalized pieces. The best physical result is stored separately from the current penalized search state. Missing-piece count always precedes material efficiency in incumbent comparison.
- Rolls minimize length at fixed width. Sheets minimize sheet count first, then occupied height on the last sheet. Sheet selection exposes each sheet separately to the existing canvas and DXF exporter. Export rejects attempts to merge a multi-sheet result into one overlapping DXF.
- All four start corners are represented by a reversible search-coordinate change. This does not mirror the delivered part. Any mode samples 5° orientations and refines around good orientations in 1° steps; exact per-part allowed angles remain authoritative. Coverage is limited by the time budget.
- The Worker yields between search operations, publishes independently checked incumbents and handles `STOP_NESTING`. Stop and deadline completion return the best valid result. The UI shows progress, missing quantities, material usage, stop status and version **v0.0.4**.

## Clearance and numerical precision

The requested gap is applied once; no separate kerf is added. Since export retains native curves, the declared polygonization error is reserved around every contour: with 0.1 mm tolerance, the polygon search uses `requested gap + 0.2 mm` and `requested margin + 0.1 mm`. This protects native curves rather than assuming a chord is the original curve. The UI explicitly describes this allowance. The NFP integer grid is 0.0001 mm; round offsets have an additional 0.0015 mm numerical guard. Contact layouts still undergo the same exact polygon distance checks.

Spline flatness is an adaptive numerical estimate, not an analytic proof for every pathological NURBS. Malformed data and subdivision limits are reported; geometry is never silently replaced by a rectangle or convex envelope. Layout quality is heuristic; there is no zero-waste or global-optimum guarantee. A synchronous polygon Boolean operation and final validation can slightly exceed the optimization deadline.

## Independent validation and tests

`validateLayout` recomputes rotation/translation independently of the search transform, intersects complete polygon solids, and exhaustively measures relevant edge distances. It checks counts, unique instances, sheet indices, rotations, margins, overlap and gaps. The validator does not call the search's `fits` or `shapesConflict`.

Passed:

- `npm test`: legacy nesting and DXF export regressions, plus new GLS and Worker checks.
- `npm run test:gls`: nonconvex and holed NFP grid comparisons, IFP, cache keys, cavity filling, all corners, exact angle restrictions, multi-sheet layout, roll trimming, actual GLS penalty updates, missing-count objective and cancellation.

## Same-budget benchmark

Only one real DXF example was available in repository history: `00.dxf`, 32 parts. Its working-tree deletion was preserved; tests read the reference from commit `84ade18` (or `NESTING_DXF`). Synthetic tests cover shapes not present in this file. Raw results: [benchmark-v0.0.4.json](benchmark-v0.0.4.json).

Both engines received identical 0.1 mm polygons, a 1400 mm width, 0.3 mm requested gap, 1 mm requested margin, the same curve-error allowance, 0°/90° rotations, bottom-right origin and a **10,000 ms optimization budget**. Sheets were 1400 × 1000 mm. The old engine ran its existing ordered trials; only trials completed before its deadline were admitted. New-engine timings below include final independent validation, separately from the 10-second optimization budget.

| Mode | Engine | Placed | Sheets | Roll length / last sheet height | Waste | Total time |
|---|---|---:|---:|---:|---:|---:|
| Roll | v0.0.3 | 32/32 | — | 885.918 mm | 32.817% | 10.000 s |
| Roll | NFP + GLS | 32/32 | — | 865.728 mm | 31.250% | 10.104 s |
| Sheet | v0.0.3 | 32/32 | 1 | 884.818 mm | 40.481% | 10.000 s |
| Sheet | NFP + GLS | 32/32 | 1 | 864.628 mm | 40.481% | 10.080 s |

This run saved **20.190 mm of roll length (2.28%)**. Fixed-sheet waste remained unchanged because the same parts used one sheet; the remaining contiguous strip increased. Runtime and achieved quality vary with machine load, geometry and budget. Four GLS penalty updates occurred in each new-engine benchmark run.

## Algorithm references

- [Voudouris and Tsang: Guided Local Search](https://www.bracil.net/CSP/papers/VouTsa-GlsTsP-Ejor99.pdf): augmented objective, maximum-utility feature penalties and local-minimum escape.
- [Mapbox Earcut](https://github.com/mapbox/earcut): triangulation with holes and deviation checks.
- [Clipper JavaScript implementation](https://github.com/junmer/clipper-lib): integer polygon Boolean and offset operations.
